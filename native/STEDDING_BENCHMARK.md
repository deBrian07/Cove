# Cove benchmark against Stedding

## Scope and evidence

This is a source and documentation review of Stedding at [`f301a37`](https://github.com/ysalitrynskyi/stedding-browser/tree/f301a37ce926c042d56ce115abb2b7517a8300f7), version `0.3.0-beta.21`, and Cove's current handoff and patches through 0078. Stedding was not built or tested for this comparison. Its feature status and test coverage below are claims recorded in its repository, not independent verification. The final 0078 native build and renderer smoke passed. The newest command workflows still await GUI acceptance because native automation cannot attach to the QA window; performance acceptance remains incomplete.

## Current read

Stedding is ahead on feature breadth and release readiness: its pinned source documents per-Space storage sessions, cross-Space command-bar navigation, nested and draggable folders, split-by-drag, Arc import, and signed macOS releases with updating. Cove has demonstrated live page preservation while switching Spaces and has a native two-pane workflow, but still lacks reliable Space restoration after restart, full pin/folder organization, and distributable signed builds. Cove should aim to beat Stedding on command responsiveness and reliability while closing these capability gaps; today's evidence does not show Cove is better overall.

## Acceptance checks for “better than Stedding”

1. **Focus and latency:** attach to the final native build, then recheck immediate typing after the Cmd+L reveal followed by Cmd+T on the cached native palette. Close/reopen the palette and browser window repeatedly, including after theme updates, to cover the ownership fix. Repeat with sidebar collapsed, during expansion, after Escape and after URL submission. No character may land in the wrong field; Cmd+L must select the URL. Measure `Show()` invocation, first paint and input-ready as separate intervals in matched release builds. Pass the ≤4 ms median/≤5 ms p95 `Show()` and ≤80 ms median/≤100 ms p95 input-ready targets above, over at least 20 cold and 20 warm openings.
2. **Space ownership:** save two Spaces with different site cookies, live forms, history, folders and a split. Restart and crash-restore; verify ownership, cookies, page state and active Space per window. Cancel an unload prompt and verify the original live page remains. Exercise opposite-direction swipes, momentum, vertical scrolling, first/last Space boundaries, rapid switches and reduced motion; verify drafts/history survive and Favorites stay fixed during the slide.
3. **Organization:** exercise nested folder create/rename/remove, tab and folder drag/reorder, pin/unpin, pin navigation and home reset, and folder/pin placement across Spaces. Restart between actions and compare exact order and homes.
4. **Splits:** drag tabs from both sidebar and tab strip into either pane; verify joined-row membership, pane-specific URL focus, swap/separate/close and restore, including folders and pinned tabs.
5. **Release quality:** run the same named tests on macOS and any claimed additional platform. Produce signed/notarized packages and verify update, rollback and profile-preserving upgrade. Publish the Chromium pin, test results, latency protocol and security support window with each release.

Passing these checks would close the specific gaps visible in this snapshot. It would not establish general browser security or complete Arc parity by itself.
